Tu es un développeur full-stack senior. Construis une application web de messagerie de support (type Telegram) en PWA installable, pour la plateforme Biz Connect Academy. Code propre, modulaire, commenté, prêt pour la production.

## 1. STACK
- Backend : Node.js (18+) + Express + Socket.IO (temps réel)
- Base de données : PostgreSQL (ou MySQL si compatible Cybrancee), via Prisma ou Sequelize, avec migrations
- Frontend : HTML/CSS/JS moderne (ou React + Vite), mobile-first, PWA (manifest + service worker)
- Notifications push : Web Push (VAPID, librairie web-push)
- Fichiers (images, vocaux) : stockage disque privé hors dossier public (/storage), métadonnées en base
- Configuration par variables d'environnement (.env), aucun secret dans le code
- Le projet doit démarrer avec `npm install && npm start` (compatible hébergement Node.js Cybrancee/Plesk, port via process.env.PORT). Fournis un README de déploiement.

## 2. CHARTE GRAPHIQUE
- Bleu (#1E5EFF), vert (#16A34A), or (#D4AF37), fond clair/sombre
- Messages envoyés = bulles bleues (à droite) ; messages reçus = bulles vertes (à gauche)
- Or pour les accents : badges de non lus, boutons principaux, favoris, en-têtes
- Interface fidèle à Telegram : liste de conversations, en-tête avec avatar, zone de saisie avec boutons pièce jointe/micro/envoyer, animations fluides

## 3. AUTHENTIFICATION
- Écran de connexion : « Nom d'utilisateur Biz Connect Academy » + « Numéro Biz Connect Academy »
- Vérifier ces informations (table users, ou appel API de la plateforme via une fonction isolée facile à brancher)
- Après la première connexion réussie : session persistante (JWT en cookie httpOnly + refresh, durée longue). L'utilisateur ne ressaisit plus rien, il ouvre l'app et voit directement ses messages
- Bouton de déconnexion dans le menu
- Compte administrateur/support séparé (identifiant + mot de passe hashé bcrypt), créé par script de seed
- Rate limiting sur le login, protection brute force

## 4. CÔTÉ UTILISATEUR
- Une seule conversation avec le support, style Telegram
- Envoi de : texte, messages vocaux (enregistrement via MediaRecorder, maintien du bouton micro, durée affichée, lecteur audio avec barre de progression), images (aperçu avant envoi, compression côté client)
- Statut du support dans l'en-tête : « En ligne » ou « Vu dernièrement le JJ/MM à HH:MM »
- Indicateurs : envoyé / reçu / lu (coches), « le support écrit… »
- Photo de profil modifiable (upload, recadrage, redimensionnement)

## 5. CÔTÉ ADMIN / SUPPORT
- Fil de messagerie listant tous les utilisateurs ayant écrit (affichés par nom d'utilisateur), triés par dernier message
- Chaque ligne : avatar, nom d'utilisateur, aperçu du dernier message, heure, badge doré du nombre de messages non lus
- Filtres : Toutes / Non lues / Lues / Favoris ; recherche par nom d'utilisateur
- Mise en favori d'une conversation (étoile, swipe ou menu)
- À l'ouverture d'une conversation : en-tête avec nom d'utilisateur + numéro de téléphone de l'utilisateur
- Le support voit aussi le statut en ligne / dernière connexion de l'utilisateur
- Plusieurs agents support possibles (rôle admin)

## 6. FIL DE MESSAGERIE (les deux côtés)
- Compteur de messages non lus par conversation, remis à zéro à l'ouverture
- Mise à jour en temps réel via Socket.IO (nouveau message, lu, présence)

## 7. COMPORTEMENT DES MESSAGES
- E-mails, liens (http/https) et numéros de téléphone détectés automatiquement et cliquables : mailto:, lien externe, tel:
- Images : s'ouvrent dans une visionneuse plein écran INTERNE au chat (aucun nouvel onglet), bouton retour/fermeture
- Appui long sur l'image : aucun menu natif (« copier le lien », « ouvrir dans un nouvel onglet »…) → désactiver contextmenu, user-select, -webkit-touch-callout, draggable, et servir les images via un blob/URL protégée
- Menu « trois points » dans la visionneuse : « Enregistrer dans la galerie » (téléchargement contrôlé), partager, etc.

## 8. NOTIFICATIONS
- À la première visite : bannière/notification invitant à installer l'application (événement beforeinstallprompt ; message d'aide spécifique pour iOS « Partager → Sur l'écran d'accueil »)
- Demande de permission de notifications au bon moment (après connexion)
- Notification push à chaque nouveau message, avec son/vibration (fichier audio de notification, vibrate pattern), même application fermée (service worker)
- Badge de messages non lus sur l'icône de l'app (Badging API) et dans le titre de l'onglet
- Clic sur la notification → ouvre directement la conversation

## 9. SÉCURITÉ (priorité haute)
- HTTPS obligatoire, helmet, CORS restreint, CSRF, validation/sanitisation de toutes les entrées (anti-XSS, anti-injection SQL)
- Mots de passe admin hashés (bcrypt), JWT signés, cookies httpOnly + secure + sameSite
- Fichiers privés : accès uniquement via routes authentifiées, vérification que l'utilisateur est propriétaire de la conversation (ou admin)
- Contrôle du type MIME et de la taille (images ≤ 5 Mo, vocaux ≤ 5 min), noms de fichiers aléatoires (UUID)
- Chiffrement des fichiers au repos (AES-256) si possible, sauvegardes de la base
- Journalisation des erreurs et des connexions, rate limiting global

## 10. BASE DE DONNÉES (tables)
users, admins, conversations (user_id, favoris, last_message_at), messages (type text/image/voice, contenu, file_id, statut, timestamps), files, push_subscriptions, presence (last_seen)
Index sur conversation_id, created_at, is_read.

## 11. LIVRABLES
- Code structuré (routes, controllers, services, middlewares, public/)
- Script de seed (admin + utilisateurs de test)
- Fichier .env.example
- README : lancement local sur Replit + déploiement pas à pas sur Cybrancee (Node.js sous Plesk, variables d'environnement, base de données, SSL, Socket.IO/WebSocket)
- Procède étape par étape : 1) base + auth, 2) chat texte temps réel, 3) images + vocaux, 4) fil admin + favoris + non lus, 5) PWA + notifications, 6) sécurité et finitions. Teste chaque étape avant de passer à la suivante.
